# Изменения translator-service

## 2026-10-11

Добавлен собственный HTTPS/mTLS Swagger операционного API в существующем контейнере без прокси и новых доменных endpoints; прежний частный HTTP сохранён. Оба listener имеют общий жизненный цикл и закрываются при отказе одного. Файлы Swagger UI 5.33.1 закреплены SHA-256 и отдаются локально без CDN; операторская CA/удостоверение отделены от издателя и не передаются оболочкой. Ревизия 3 публикует собственную ссылку группы и API. Добавлены локальная подготовка PKI без перезаписи, настройка живого env, регрессии и эксплуатационные инструкции. Модель, Kafka-контракты, очереди, SQL и версии ОС/Python не меняются.

- 2026-10-10: верхняя строка собственного состояния переименована в «Перевод текстов» (`Text translation`), ревизия описания 2. Продукты видны внутри прежнего состава; UUID, identity, журнал и последовательность не меняются. Таблица переименований в оболочке не создаётся.

## 2026-10-10

Добавлены независимая optional-роль UI-публикации, собственная техническая проекция присутствия ролей/локальной модели, миграция 0003 и read-only `/v1/components`. Проекция перестраивается heartbeat и сохраняет только сутки технических строк; задания/результаты не удаляются. Издатель не знает потребителей, использует собственные identity/outbox и публичный закреплённый wheel внутри своего образа. Добавлены сервисные Python-проверки присутствия и настоящей страницы при stop/start; доменные контракты не меняются.

## 2026-10-09

- Тест жизненного цикла фиксирует исходную опись Docker и после успеха, ошибки или прерывания удаляет только созданные им контейнеры, именованные и анонимные volumes и сети; исходные ресурсы и образы проверяются на сохранность. Сборка и загрузка образов вынесены в явную подготовку до теста, а запуск поверх существующих данных или удалённых рабочих endpoints запрещён. Добавлены восемь модульных проверок безопасности очистки и намеренный отказ после полного запуска ролей; mounts не дают права удалять чужой или неизвестный volume без подтверждения владения. Результат каждой проверки автоматически сохраняется также в читаемый Markdown. Подтверждённые остатки прежних прогонов удалены адресно; чужие контейнеры, рабочие образы, секреты и кеш сохранены.

- Базовые результаты pytest и регрессия повторного Kafka provisioning оформлены в Markdown по образцу ранее проверенных инфраструктурных компонентов. Отчёты содержат время, команду, итог, длительность, сценарии и ограничения; исходные JUnit XML сохранены в `test/obsolete`, все входящие ссылки обновлены. Переоформление не меняет результаты и не считается новым запуском тестов.

- Устранены лишние уровни запуска: осталось два Compose-файла, канонические определения находятся в `compose.remote.yml`, а `compose.yml` добавляет Kafka и обязательную собственную БД. Удалены три промежуточных Compose-файла, настройка собственного env-пути и неиспользуемая build-stage; старый runtime-patch архивирован. Исправлен локальный запуск topic provisioner, добавлены явная `cleanup.policy=delete` и структурированный журнал; из CI убраны повторные пути и зависимость от общего PostgreSQL. В `test` сохранены отчёт и настоящий JUnit-результат: 10 конфигурационных и 30 модульных/SQL-проверок пройдены без пропусков; статические проверки успешны, одноразовая БД удалена. README и схема соответствуют текущей поставке.
- Дождались загрузки закреплённой MADLAD и собрали полный runtime. Python-тест жизненного цикла использует реальные поставки Kafka и translator-service с рабочими `.env` и постоянными данными, не создаёт тестовые копии инфраструктуры и не удаляет ресурсы. Полный прогон прошёл 68 этапов: оба инициализатора, обе очереди, повтор результата без вычисления, полный перезапуск и восстановление доставки после отказа Kafka. Исправлен выявленный отказ повторного provisioning при пустом `create_topics`, отдельная регрессия пройдена. Предыдущие неуспешные прогоны и итоговый успешный результат сохранены в `test`; смысловая добавка страны в переводе MADLAD зарегистрирована как отдельный незакрытый вопрос качества, а не скрыта успешным транспортным тестом.

- По ADR-0097 обычный Compose translator-service включает каноническую Kafka с её отдельным `.env`, запускает собственную PostgreSQL без профиля и автоматически применяет topics после Kafka healthcheck; consumer, outbox и API ждут успешного provisioner.
- Добавлен `compose.remote.yml` для Kafka на другом узле: локальный broker не создаётся, фактический endpoint проверяется provisioner, а `/readyz` требует доступных БД, Kafka и трёх topics.
- Каталоги `tests` и `test` объединены в единый `test`; основной Docker build context исключает его через `.dockerignore`, а test-stage получает проверки только через явный именованный BuildKit-контекст. Node.js остаётся только в test-stage как runtime закреплённого Pyright и не входит в production-stage.
- По ADR-0096 translator-service стал владельцем контракта и provisioning двух входных topics и одного topic результатов без списка прикладных клиентов; в v1 совместимо добавлена общая операция `TRANSLATE_TEXT`.
- Добавлены независимые приоритетный и обычный consumer, транзакционное чередование классов без голодания обычной очереди и совместимость прежнего `translation.requests.v1`.
- Поставка получила собственную PostgreSQL, живой `.env`, файловый пароль, одноразовый Kafka provisioner и read-only операционный API.
- Вычислительная пара model + worker определена как переносимая единица горизонтального масштабирования; общий межузловой Unix socket запрещён.

## 2026-10-08

- По ADR-0090 публичные переменные Compose приведены к `AELEV_INFRASTRUCTURE_TRANSLATOR_*`; `.env.example` содержит только настройки самостоятельного translator-service, а пароль роли общей локальной БД принадлежит оркестрации.
- По ADR-0087 компонент перенесён в `services/infrastructure/translator-service` как общий вспомогательный переводчик.
- По ADR-0088 добавлены собственные `compose.yml` и `.env.example`; корневой Compose только оркестрирует ту же поставку, а отдельный запуск принимает удалённые PostgreSQL и Kafka endpoints.
- Прежний provision-скрипт и монолитная конфигурация архивированы; Kafka-контракт, отдельная БД, миграция, offline runtime, модельный lock и внутренний socket сохранены.

## 2026-10-07

- MADLAD и закреплённый offline runtime выделены из base-screening в самостоятельную поставку.
- Добавлены устойчивые Kafka-задания/результаты, собственная БД, lease, повторы без вычисления и управление процессом.
- Повтор после timeout не вытесняет уже ожидающие задания; границы очереди и сохранность проверяются отдельно от качества перевода.
- Проверка готовности требует завершённой загрузки дочернего runtime; реальные запросы, времена и ограничения зафиксированы в [исторической рабочей проверке](obsolete/LOCAL_VALIDATION.md).
- Готовые локализации и человеческие решения сохраняются у прежнего владельца; модель и критерии не меняются.
