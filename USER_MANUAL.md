# Руководство translator-service

Локальный Swagger без установки клиентского сертификата: [полная настройка и команды](README.md#локальный-swagger-без-клиентского-сертификата). Откройте `http://127.0.0.1:18496/docs`, нажмите `Authorize` и войдите через существующий Keycloak своим оператором с назначенным `operator-read`. Без собственного токена операции возвращают 401; право оболочки не заменяет право API. HTTP допускается только в явно выбранной локальной установке на loopback, не для удалённого сервера. IdP сохраняет HTTPS, корпоративные ограничения браузера не обходятся.

Общий инфраструктурный компонент выполняет технические задания на перевод и не знает, какой клиент или предметный процесс использует результат. Межсервисные задания и результаты проходят только через принадлежащие translator-service Kafka topics. Операторский Swagger по [ADR-0109](../../../docs/adr/20261011-0109-operator-translation-through-kafka.md) может отправить собственный запрос в ту же очередь и дождаться перевода; частный HTTP backend остаётся только для диагностики.

## Установка и запуск

Исходники, собственная PostgreSQL, миграции, закреплённые схемы, `compose.yml` и `.env.example` находятся в этом каталоге. Команды ниже выполняются из него после подготовки env, файлового пароля и выбранного TLS/OIDC-режима по [README](README.md#подготовка-и-запуск). Существующие настройки и секреты не перезаписывайте. Обычный запуск автоматически поднимает Kafka из соседней канонической поставки, ждёт её готовности и применяет topics; вручную запускать provisioner не требуется. Если тома уже заняты корневой оркестрацией, используйте её проект, а не создавайте второго писателя. Секреты не публикуются.

```sh
docker compose --env-file .env config --quiet
docker compose --env-file .env up --build -d --wait --wait-timeout 600
docker compose --env-file .env ps
```

`translator-migrator` выполняется до рабочих ролей и не повторяется бесконечно. `translator-topic-provisioner` ждёт healthy Kafka, при ошибке соединения повторяется и не пропускает consumer, outbox или API дальше. `translator-model` и `translator-api` должны стать healthy; оба consumer, worker и outbox должны работать. Новые задания сохраняются даже при временной недоступности модели. Перезапуск вычислительной ячейки не требует перезапуска клиентов.

Если Kafka находится на другом сервере, используйте отдельную точку запуска с собственной локальной БД по [README](README.md#подготовка-и-запуск): она не запускает Kafka на узле переводчика и проверяет реальный endpoint. Защищённый broker должен уже существовать: текущий Kafka Compose не добавляет TLS автоматически. Удалённая PostgreSQL и несколько ячеек на разных hosts пока требуют отдельной исправленной сетевой поставки; ограничения internal-сети зафиксированы там же. Установка адреса удалённой БД сама по себе не обеспечивает мигратору и worker доступ к ней.

## Что происходит с заданием

Обычный независимый запрос использует `TRANSLATE_TEXT` и содержит исходный язык, целевой язык и текст. Значения `PROFILE_UNIT` и `OPERATOR_REVIEW` сохранены только для совместимости v1. Срочный запрос публикуется в `translation.requests.priority.v1`, обычный — в `translation.requests.v1`; payload у них одинаков. Соответствующий consumer сохраняет запрос, worker получает ограниченную аренду, model вычисляет перевод, а outbox публикует сохранённый результат. После настроенной серии срочных заданий готовое обычное задание обслуживается обязательно. Повтор готового запроса возвращает тот же ответ без вычисления.

`PENDING` означает ожидание, `RUNNING` — активную попытку, `SUCCEEDED` — готовый результат, `FAILED` — доказуемую ошибку входа или непригодный выход модели. Временный технический сбой автоматически повторяется и не создаёт отменённой карточки. Готовый перевод ещё не доказывает правильность смысла; итоговую проверку локализации выполняет её владелец.

## Статус, пауза и продолжение

### Группы и операции Swagger

В `/docs` группы расположены в порядке `default`, `translator`, `metrics`. Операторский режим требует собственной авторизации по [README](README.md#swagger-операционного-api); группировка не меняет права доступа или ответы.

| Группа | Endpoint | Что показывает |
|---|---|---|
| `default` | `GET /healthz` | API отвечает. Это не проверка БД, Kafka или модели. |
| `default` | `GET /readyz` | Собственная БД, broker Kafka и три topics доступны; при отказе — 503. Готовность модели и продвижение заданий этим не подтверждаются. |
| `default` | `GET /v1/components` | Наблюдения присутствия `priority-consumer`, `normal-consumer`, `worker`, `outbox`, `model`: `state` и время `observed_at`. Устаревшее/отсутствующее наблюдение означает `UNKNOWN` и `observed_at=null`, а не доказанную остановку. |
| `default` | `GET /v1/status` | `control.desired_state` — разрешена ли выдача новых заданий; `revision` — ревизия управления; `priority_streak` — текущая серия срочных выдач. `jobs` содержит числа заданий по состоянию и очереди, например `PENDING:normal`. Отсутствующая комбинация означает отсутствие таких заданий. |
| `translator` | `POST /v1/translate` | Операторский перевод через выбранную очередь Kafka. Требует отдельного `operator-translate`; частный listener не предоставляет этот endpoint. |
| `metrics` | `GET /metrics` | Числа заданий в формате Prometheus: `aelev_translator_jobs` с метками `state` и `queue`. |

`/v1/status` и `/v1/components` полезны вместе: очередь может накапливаться при живых исполнителях, а API может отвечать при отсутствующем worker. Heartbeat означает присутствие, не отсутствие зависания или успешное вычисление; модель проверяется внутри собственной вычислительной ячейки. Эти ответы не содержат текстов заданий, готовых переводов или сведений о клиентах и не заменяют итоговую проверку качества перевода.

### Управление выдачей заданий

Команды выполняются только человеком с разрешённым эксплуатационным доступом к инфраструктуре. CLI не является публичным HTTP-интерфейсом и не даёт доступ к чужим хранилищам. Прочитайте состояние и текущую ревизию:

```sh
curl --fail http://127.0.0.1:8096/v1/status
```

Чтобы прекратить выдачу новых заданий, сохраните PAUSE с уникальным идентификатором, своей идентичностью, причиной и ожидаемой ревизией. Активная единица может завершиться. Вместо PAUSE используйте RESUME для продолжения; ожидаемую ревизию берите из нового статуса, а не копируйте прежнее число.

```sh
docker compose --env-file .env exec translator-priority-consumer \
  python -m translator_service.runtime control \
  --action PAUSE --command-id maintenance-1 --actor operator \
  --expected-revision 1 --rationale planned-maintenance
```

RESET возвращает только незавершённую работу в очередь. Сначала выполните PAUSE и дождитесь отсутствия активных аренд, затем отправьте RESET с текущей ревизией, новым идентификатором и причиной; после этого отправьте RESUME. Готовые результаты и история не стираются. Конфликт ревизии требует перечитать статус. Повтор того же идентификатора допустим только с точно тем же телом команды.

## Операторский перевод

Владелец сначала явно включает `API_TRANSLATION_ENABLED=true` и выполняет настройку из [README](README.md#операторский-перевод). При `false` POST не показывается и недоступен; пять диагностических GET сохраняются. В текущем локальном стенде операторский перевод включён.

Настройте собственные OIDC и пределы по [README](README.md#операторский-перевод), выполните `translator-api-provision` и войдите через `Authorize`. Настроенному `API_OPERATOR_USER` задача явно назначает два отдельных права; прочие пользователи не получают право перевода автоматически. `operator-read` позволяет читать диагностику, но не отправлять текст; `operator-translate` разрешает POST, но не подменяет право чтения. В HTTPS-режиме клиентского сертификата для POST недостаточно: нужен также собственный токен.

Откройте `translator` → `POST /v1/translate` → `Try it out`, замените тело запроса и нажмите `Execute`:

```json
{
  "source_language": "en",
  "target_language": "de",
  "queue": "normal",
  "text": "Hello, world!"
}
```

`source_language` — код исходного языка, `target_language` — код целевого языка. Коды используют строчные буквы и собственный протокол модели, например `en`, `de`, `ru`. `queue` выбирает только `normal` или `priority`; срочность не означает прерывание уже выполняющегося задания. `text` — точный исходный текст до 12 000 символов, не только пробелы. Для приоритетного задания замените `normal` на `priority`; имя topic, чужой идентификатор и модель передавать нельзя.

Ответ 200 содержит перевод в `translated_text`, UUID `request_id`, языки, очередь, точный `translator_ref` и предупреждения `warnings`. Ответ появляется после полного штатного пути и Kafka ACK результата, не после прямого обращения к модели. Действующая модель — Index-Translate 9B; её точный выпуск выбирается автоматически из собственного lock. Готовый текст не доказывает смысловую точность: проверяйте результат так же, как любой иной перевод. Поддерживаемые языковые коды, ограничения и смена модели описаны в [README](README.md#сравнение-моделей-и-обновление-весов).

Если получили 429, API отказал до постановки из-за текущей нагрузки. 422 сообщает неверный ввод или доказуемую ошибку перевода. 503 может означать неподтверждённую доставку, а 504 — превышение времени ожидания; в этих случаях задание могло остаться в очереди и продолжить работу. Отключение браузера его не отменяет. Сохраните `detail.request_id` для диагностики; не воспринимайте ошибку ожидания как доказанную отмену. Каждый новый POST — новое намерение и новое задание, а не идемпотентный повтор; автоматической повторной отправки нет. Точная таблица ошибок и пределы находятся в [контракте](../../../docs/api/translation.md#операторский-перевод).

## Диагностика и восстановление

```sh
docker compose --env-file .env logs --tail 30 \
  translator-priority-consumer translator-normal-consumer \
  translator-worker translator-outbox translator-model
docker compose --env-file .env exec translator-priority-consumer \
  python -m translator_service.runtime health
```

При недоступности БД consumer не подтверждает Kafka offset и перезапускается; после восстановления он продолжает с сохранённой позиции. При недоступности модели задание повторяется автоматически, при зависании вычисления срабатывает ограниченный timeout. Неподдерживаемый язык или неверный контракт не принимаются за успешную локализацию: проверьте технический код и точную модель, не подменяйте результат вручную. Обычные логи не содержат исходных текстов, SQL или паролей.

Резервную копию своей БД восстанавливайте в отдельный изолированный экземпляр, без доступа к рабочим topics. Сохраните точные схемы и модель. Проверка `python -m translator_service.runtime verify-restored-state` должна вернуть `VERIFIED`; она не исправляет и не публикует данные. Незавершённые аренды после восстановления повторяются, готовые результаты сохраняются. Порядок и команды изолированной проверки приведены в [README](README.md).

Для адресной штатной остановки из этого каталога используйте `docker compose --env-file .env stop translator-priority-consumer translator-normal-consumer translator-worker translator-outbox translator-model translator-api`. Не удаляйте БД, Kafka-журналы или volumes: остановка процесса не означает удаление истории. Production требует защищённых endpoints и отдельных identities; локальный PLAINTEXT не переносится в production.
