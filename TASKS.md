# translator-service: работа и ворота поставки

Архитектурная истина — [SPEC](SPEC.md), а не этот список.

- [x] Собственные исходники MADLAD, Cargo/Poetry lock, Dockerfile, `compose.yml` и `.env.example`; корневой инфраструктурный Compose только оркестрирует ту же поставку.
- [x] Перенос в `services/infrastructure/translator-service` по ADR-0087 без изменения Kafka-контракта, модели и сохранённых данных.
- [x] Публичные Kafka requests/results из единственного источника shared/contracts.
- [x] Собственная миграция, идемпотентный вход, ограждённый lease, транзакционный результат/outbox и повтор без вычисления.
- [x] Собственные PAUSE/RESUME/RESET и read-only проверка восстановленного состояния.
- [x] Измеренная рабочая проверка выделения и сохранения локализаций, с отдельной фиксацией незавершённых длинных переводов в [отчёте](LOCAL_VALIDATION.md).
- [ ] Полная наблюдаемость компонента: метрики очереди и задержки, инфраструктурные traces и проверки состояния транспортных ролей.
- [ ] Отдельно измерить и улучшить длинные переводы: при текущей нагрузке встречаются timeout 180 секунд; очередь повторяется, но такой результат не считается завершённым переводом или подтверждением качества.
- [ ] Production: SPIFFE/mTLS/ACL, защищённые подписи и независимые failure-domain backup/restore.
