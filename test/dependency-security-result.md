## Изменение

PyJWT 2.10.1 заменён на 2.15.1. Сравнение полных записей Poetry lock подтвердило, что изменён только `pyjwt`: остальные версии, зависимости и контрольные суммы пакетов сохранены. FastAPI 0.141.1, Starlette 1.3.1, криптография, модель, контракт, SQL, Dockerfile, ОС и Python не изменены. Версия 2.15.1 включает исправления 2.15.0 и восстановление поддержки стандартного Base64URL padding.

Первые 20 пропусков обычного тестового образа не объявлены успехом: девять SQL-зависимых случаев и 11 конфигурационных случаев проверены отдельно.

Новые случаи находятся в [test_operator_auth.py](test_operator_auth.py): неизвестный `kid` при повторах одного или разных значений больше не вызывает получение JWKS на каждый запрос; повреждённый RSA JWK не блокирует действительный ключ; неизвестное обязательное расширение токена отвергается. Сохраняются нормальная ротация после стандартного 30-секундного интервала refresh, действительная RSA-подпись с padding и прежний отказ HS256 до обращения за ключами. RSA-ключи создаются в памяти; HTTP-ответы JWKS ограниченно подставлены тестом. Нет обращений к настоящему Keycloak, публикаций заданий или нагрузочной атаки.

SQL выполнен на настоящей PostgreSQL 17.6-alpine в отдельной закрытой сети, без опубликованных портов и без доступа к рабочей БД/Kafka. Данные находятся только в tmpfs; применены штатные Alembic-миграции. Контейнер, сеть и временный файл проверочного секрета удалены; отсутствие контейнера и сети проверено отдельно. Первоначальная ошибка конфигурационного окружения из-за недоставленного `api.py` исправлена добавлением публичного файла, не правкой теста или Compose. Замечания форматирования и частного импорта исправлены только в новом тесте, затем проверки повторены.

## Повторение

Из каталога сервиса используйте штатный тестовый этап и команды README:

```sh
docker build --build-context translator_tests=./test --target test -t aelev-translator-security-checks .
docker run --rm --network none aelev-translator-security-checks
docker run --rm --network none aelev-translator-security-checks poetry run pytest -q test/test_operator_auth.py
docker run --rm --network none aelev-translator-security-checks poetry run ruff check src test alembic
docker run --rm --network none aelev-translator-security-checks poetry run ruff format --check src test alembic
docker run --rm --network none aelev-translator-security-checks poetry run pyright src test
```

SQL требует явно изолированной `translator_test` с миграциями и `AELEV_TRANSLATOR_TEST_DATABASE_URL`; рабочую БД использовать нельзя. Точный рецепт закреплён в [сервисном CI](../../../../.github/workflows/translator-service-validation.yml), правила разделения SQL и Compose — в [README](../USER_MANUAL.md#диагностика-и-восстановление). Для сравнения исходной версии используйте отдельный checkout указанной ревизии и тот же набор новых тестов, не меняйте рабочий lock туда и обратно.

Свежий список GitHub содержал 15 предупреждений PyJWT; новая версия не попадает ни в один их уязвимый диапазон. [Общая сверка](../../../../docs/reports/dependency-security-2026-10-12.md) охватывает все 33 записи текущего снимка. Предупреждения устаревания httpx/AnyIO в тестовом клиенте оставлены видимыми и не являются этими предупреждениями безопасности. Повтор настоящего браузерного входа, перевода рабочей моделью, WAN и полный аудит ОС не выполнялись; данные, телеметрия и рабочие процессы сохранены.
