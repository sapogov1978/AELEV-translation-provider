# Руководство: Сравнение моделей перевода

Исторический эксперимент сравнил прежний MADLAD400 3B Q4_K из собственного неизменяемого образа и официальные Index-Translate 2B/9B Q4_K_M. После оценки оператор отдельно выбрал 9B по [ADR-0112](../../../../../docs/adr/20261011-0112-index-translate-9b.md); сырые результаты и условия этого эксперимента не переписываются. Это проверка вычислителей, не полный тест Kafka-поставки. Старый MADLAD-образ не сохраняется по требованию оператора: повторение исторического сравнения потребует отдельно получить прежний выпуск, а текущий рабочий образ нельзя назвать прежней моделью. По умолчанию рабочие контейнеры не останавливаются; отдельно разрешённое окно освобождения памяти описано ниже. Очередь, БД, API, удостоверения и `translator.lock.json` экспериментом не изменяются.

## Что измеряется

Один фиксированный [набор из 20 текстов](cases.json), шесть исходных языков, восемь языковых направлений, два вычисления каждого текста после отдельного прогрева. Проверяются отрицания, числа, неоднозначность, неопределённость, идентификаторы, placeholders и прежняя добавка страны к `central bank`. Исходные тексты синтетические, не данные потребителя инфраструктуры. Точные проверки литералов — только часть проверки, не автоматическая оценка всего смысла; трактовка и естественность каждого перевода проверяются отдельно по сырым результатам.

Модели запускаются последовательно на CPU с одинаковым ограничением 2 CPU и двумя вычислительными потоками, без GPU и внешней сети. На каждую генерацию разрешены 192 выходных токена; токенизаторы разные, поэтому этот предел не означает одинаковый объём текста. MADLAD использует прежний целевой токен и разбиение по абзацам, Index — официальный шаблон с явным исходным/целевым языком, `temperature=0`, отключённым thinking и контекстом 2048 токенов. Кэш результатов MADLAD не используется; кэш подсказки Index выключен. Сохраняются точные ответы, признак ограничения длины Index и оба повтора; обрезанные результаты не считаются полными переводами.

Измеряются загрузка процесса, отдельный прогрев, время каждого перевода, p50/p95 и пиковая память cgroup. У кандидатов дополнительно записываются RSS и VmHWM из `/proc/<pid>/status`; первый завершённый MADLAD-прогон этих полей не содержит. Загрузка файлов и проверка хешей не входят в задержку перевода. Память cgroup включает учитываемый файловый кэш; это не только размер весов и не точный RSS, а ранее прочитанные mmap-страницы могут учитываться в другом cgroup. Работающие фоновые процессы и Docker VM влияют на результаты: локальная небольшая выборка не подтверждает SLO, GPU-производительность, все 150/419 языков или качество полной точности. Q4_K и Q4_K_M не являются идентичной квантизацией.

## Подготовка и запуск

Изолированный downloader закрепляет filelock 4.2.1 в собственном `poetry.lock`; это исправление безопасности эксперимента, не смена рабочих зависимостей или выбранной модели переводчика. Прямая зависимость не добавляется, новые переводы и загрузка моделей при проверке lock не запускаются.

Нужны Docker и операторский Python со стандартной библиотекой. Вычисления выполняются на принятом Python 3.13.7 / Debian Bookworm внутри контейнеров; версия установленного на станции интерпретатора не изменяется. Не нужен доступ к рабочему Swagger или пароль. Сначала проверьте `docker info`, `python3 --version` и свободное место. Дополнительные веса занимают около 7,1 ГБ, отдельная сборка и промежуточные файлы загрузки требуют запаса диска. Лимиты моделей: MADLAD 4 ГиБ, Index 2B 3 ГиБ, Index 9B 6,5 ГиБ, без контейнерного swap. Не запускайте 9B, если работающая инфраструктура вместе с этой памятью не помещается в Docker VM с запасом; сценарий не останавливает другие сервисы и не увеличивает VM.

Из каталога `translator-service`:

```sh
python3 test/model_comparison/run.py prepare
docker image inspect <тег-восстановленного-MADLAD> --format '{{.Id}}'
python3 test/model_comparison/run.py run --madlad-image sha256:<идентификатор-собственного-образа>
python3 test/model_comparison/run.py clean
```

Если загрузка и сборка уже выполняются отдельной командой, после готовности экспериментального образа можно добавить к `run` явный `--wait-for-artifacts`: MADLAD начнёт вычисления сразу, каждый следующий кандидат будет ждать своего завершённого проверенного файла не более восьми часов. Ожидание не включает публичный listener и не создаёт контейнер с неполными весами. Состояние проверок фиксируется в [отчёте](validation-result.md); не изменяйте корпус или параметры сценария во время прогона.

После прерывания можно продолжить `run` с `--resume` и тем же неизменяемым `--madlad-image`. Сценарий повторно использует только полностью завершённые результаты из `result.json`, если совпали корпус, модельный манифест, lock исторического MADLAD-образа, ID образов и число вычислений. Предыдущая опись сохраняется в истории нового отчёта. Отсутствующая модель запускается заново; неполный прошлый результат запрещает такое продолжение.

Перед каждой моделью проверяются не только Docker stats, но и `MemAvailable` самой Docker VM: лимит модели плюс 0,5 ГиБ должны помещаться в доступную память. Недостаток памяти завершает попытку с ошибкой; сценарий не отключает контейнеры автоматически и не меняет ресурсы Docker Desktop.

Только при отдельном разрешении оператора можно добавить `--pause-compute-project <собственный-Compose-project>` к `run`. Перед остановкой обязательно проверяются полный SHA-256 9B, единственный работающий model/worker выбранного проекта, исходное здоровье модели и совпадение обоих образов с неизменяемым `--madlad-image`. Worker штатно завершается до остановки модели; срок 300 секунд позволяет закончить уже начатый запрос. В `finally` запускаются те же контейнеры с теми же образами и томами: сначала модель до healthy, затем worker. Опись, разрешённая остановка и восстановление сохраняются в `maintenance-result.json`; эксперимент не удаляет рабочие данные, не останавливает БД/транспорт и не переключает модель. Прерывание SIGINT/SIGTERM тоже проходит восстановление; SIGKILL или остановка host требуют ручной проверки по сохранённой описи.

Продолжение текущего прогона с освобождением памяти: `python3 test/model_comparison/run.py run --madlad-image <неизменяемый-ID-MADLAD> --resume --pause-compute-project <собственный-Compose-project>`. Не запускайте его до завершения проверенной загрузки. MADLAD/2B измерялись без остановки рабочего вычислителя, 9B — в разрешённое окно его остановки; одинаковый лимит 2 CPU не делает фоновую нагрузку идентичной. Времена показывают этот локальный опыт, не универсальное преимущество производительности.

Вторая команда относится только к отдельно восстановленному историческому MADLAD-образу; не передавайте изменяемый тег аргументу `--madlad-image` и не используйте текущий Index-образ. Сценарий читает lock из указанного неизменяемого образа и отказывается выдавать другую модель за MADLAD; рабочий lock не используется как описание старого вычислителя. Это клонирование исторического вычислителя для эксперимента, не обращение к рабочему socket. Сборка экспериментального движка отдельная, не входит в обычные Compose. Test-каталог уже исключён из production build context через `.dockerignore`.

Неизменяемые версии и SHA-256 находятся только в [манифесте эксперимента](models.json); Dockerfile закрепляет тот же исходный архив llama.cpp. Рабочий lock не является этим манифестом и не заменяется им. Веса скачиваются в игнорируемый `runtime/model-comparison`, проверяются на host и повторно в offline-контейнере. Несовпадение хеша/размера запрещает запуск, отсутствующий артефакт не загружается во время вычисления. Не используйте удалённый модельный API как подмену локального запуска.

Подготовка использует официальный `hf download` с Xet, версии которого принадлежат только [манифесту загрузки](pyproject.toml) и [lock-файлу](poetry.lock) эксперимента. Одноразовый контейнер загрузки имеет лимит 1 ГиБ, не получает секреты сервиса и не использует неявные токены Hugging Face. Файл сначала сохраняется в промежуточном каталоге и публикуется для вычислителя только после проверки SHA-256. После сборки `Downloader.Dockerfile` отдельную загрузку можно повторить командой `python3 test/model_comparison/run.py download --model index-9b`; эта команда не пересобирает вычислитель. Зависимости production не изменяются.

## Результаты и очистка

[Оценка всех трёх исполненных моделей](result.md), [проверки](validation-result.md), [восстановление вычислителя](maintenance-result.json) и [очистка](cleanup-result.json) относятся к завершённому прогону 2026-10-11. Веса, промежуточные файлы и два экспериментальных образа удалены; для нового прогона сначала повторите подготовку. Локальный архив первоначального частичного отчёта удалён по отдельному запросу 2026-10-12; прежняя неуспешная сверка описи остаётся в истории JSON и не превращается в успешную проверку.

Сценарий записывает `result.md`, `result.json`, отдельный JSON и журнал движка каждой модели рядом с собой. `result.md` показывает исходные тексты и все первые переводы без исправлений; JSON сохраняет каждый сырой ответ, время, память и различия повторов. Итог выполнения и смысловое качество разделены. До запуска фиксируются контейнеры с исходным временем старта, сети и тома; после исполнения опись сверяется. Временные контейнеры удаляются в `finally` только при совпадении точного имени и метки текущего прогона, включая ошибку и обычное прерывание. Контейнеры создаются без новых сетей, volumes или публичных портов.

Отдельная команда `clean` адресно удаляет собственный `runtime/model-comparison`, включая неполные загрузки и кэш клиента, только при совпадении маркера владельца, точного пути и отсутствии экспериментальных контейнеров. Каталог без маркера или подмена пути запрещают очистку. Затем удаляются только два маркированных экспериментальных образа; тест и отчёты остаются. Общего `prune`, удаления рабочих образов/данных, каталогов по маске и перезапуска Docker daemon нет. Общий BuildKit-кэш не очищается. `SIGKILL`, остановка Docker daemon или host не позволяют Python выполнить `finally`: при таком сбое оператор сначала сверяет точные имена/метки остаточных контейнеров, не удаляет их по широкому префиксу.

Модульные проверки сценария выполняются собственным service test-stage: `poetry run pytest -q test/model_comparison/test_experiment.py`. Они проверяют корпус, официальный шаблон, SHA-256/размер, точные условия, изоляцию и защиту очистки. Они не заменяют реальную загрузку и перевод обеими моделями.
