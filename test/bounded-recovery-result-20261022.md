## Согласованный объём и установленные изменения

Пользователь разрешил конечные политики вместо бесконечных, регистрацию собственных постоянных ролей в существующем ограничителе без сброса истории и запуск только прежних БД/API/издателя. Модель и worker не запускаются из-за недостатка памяти. Это не разрешение переписать задания, поменять очередь или установить новый механизм восстановления.

Исходный `compose.remote.yml` теперь ограничивает постоянные роли и подготовку topics политикой `on-failure:3`. Мигратор и другие одноразовые задачи сохраняют `no`. Четыре собственных параметра допускают меньший остаток или `no`; локальный `.env` сохраняет для прежнего заблокированного издателя `no`. Разрешение самостоятельного Compose с обычными и всеми профилями проверено вместе с меньшими остатками и отличием задач подготовки.

## Подтверждённые незавершённые части

Регистрация всех восьми постоянных ролей не выполнена: у двух consumers/worker/outbox вообще нет Docker healthcheck, модель по разрешению остаётся остановленной, а sender на стенде не установлен. Штатный оператор требует живой экземпляр с пробой; этот барьер не обходился. Ограничение native-выходов само по себе не восстанавливает зависший процесс без настоящей пробы.

Фактический SDK издателя и его `python -S` используют SQLite 3.40.1, не версию с подтверждённым исправлением WAL-reset по ADR-0115. Здоровый heartbeat и сохранный архив не закрывают эту проблему. Для лёгких проб фоновых ролей, совместимого исправления SQLite, собственной PKI/sender и сквозной доставки запрошено отдельное согласование; они не считаются установленными или проверенными этим протоколом. Полная готовность переводчика и всего стенда остаётся неподтверждённой.
