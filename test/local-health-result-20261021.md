# Локальные пробы модели и API переводчика

## Объём

По отдельному согласованию заменены только `translator-model` и `translator-api` через общий Compose инфраструктуры. Регулярная Docker-проба теперь выполняет автономный `python -S` с импортами `os`/`time`: она читает атомарный сигнал собственного цикла обслуживания, не загружает приложение и не выполняет HTTP, SQL, Kafka или TLS. Проверки готовности остаются отдельными; зелёная живость API не доказывает доступность зависимостей.

Модельный сигнал появляется только после подтверждённой загрузки прежнего нативного runtime и связывает его с инкарнацией родительского Python-процесса. Проверка отвергает смерть/зомби и повторное использование PID без ожидания истечения сигнала. Незагруженная модель не проходит пробу; зависший цикл перестаёт её обновлять. API подтверждает запуск обоих listener, а завершение одного останавливает оба и отзывает сигнал. Предел свежести — 30 секунд; прежние Docker-интервал 10 секунд, timeout 5 секунд и пороги модели/API 30/12 не повышались.

## Проверки исходников и изолированного Linux

- 279 тестов прошли, 17 внешних сценариев явно пропущены, 4 подтеста прошли; Ruff, строгий Pyright и Black для всех 55 Python-файлов прошли. Два предупреждения — импорт AnyIO до pytest и устаревающий псевдоним Starlette/AnyIO; зависимые пакеты не заменялись. В шести ранее неформатированных файлах исправлены только переносы, равенство AST проверено; адресные комментарии Pyright в тесте перенесены к нужным строкам.
- В первоначальном общем тестовом venv находился PyJWT 2.15.0 вместо собственного закреплённого 2.15.1. Полный успешный прогон использовал точный пакет и публичные Swagger-артефакты из прежнего рабочего образа в отдельном временном каталоге; общий venv и зависимости сервисов не изменены. Каталог контрактов задан явно. Первые ошибки окружения не выданы за успешный результат.
- Настоящий изолированный контейнер нового образа работал без сети, рабочих mounts и Docker socket, с read-only корнем и лимитом 256 МиБ/1 CPU. Проверены незагруженная модель, смерть фиктивного дочернего процесса, сохранение HTTP-живости при неготовности, недоступные БД/Kafka, намеренная остановка serving loop дольше 30 секунд, восстановление heartbeat и закрытие обоих listener. Настоящие веса в этом тесте не загружались; тест не выдаётся за качество перевода.
- 22 запуска отдельного probe-процесса, включая ожидаемые отрицательные: 37,034–1601,598 мс на загруженном стенде. Это измерение конкретного запуска, не гарантия максимума под любой нагрузкой. Контейнер завершён с кодом 0 и удалён штатным `--rm`.

Интерпретатор, Debian, виртуальное окружение, нативная библиотека, веса, lock, контракты, миграции, USER, CMD и environment образа не заменялись. Реальный полный путь нового перевода через Kafka в этой адресной проверке не запускался.
