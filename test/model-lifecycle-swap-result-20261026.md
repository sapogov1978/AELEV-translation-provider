# Жизненный цикл вычислителя и давление памяти — 26 октября 2026

## Согласованный объём

После [неуспешной финальной приёмки общего запуска](../../test_infrastructure/restart-result-20261026.md) владелец разрешил исправить жизненный цикл вычислителя и адресно обновить только модель переводчика, а также установить причину большого swap. Это не разрешение менять модель, ОС/Python, зависимости, БД, Kafka, чужие контейнеры или конфигурацию Docker Desktop с перезапуском daemon. Очередь Advance и Qwen не включаются.

## Исправление

`_stop_runtime` сохраняет ссылку на дочерний процесс до подтверждённого `wait`. Таймаут ожидания после `kill` больше не перекрывает исходный timeout запроса HTTP 500; повторный запуск запрещён, пока прежний процесс не завершился. Сигнал kill не посылается бесконечно. По прежнему частному протоколу возвращаются `503 / TRANSLATOR_DEADLINE_EXCEEDED` либо `TRANSLATOR_NATIVE_NOT_READY`; установленный worker уже распознаёт их, поэтому его обновление не требуется. Собственный журнал различает незавершённую остановку и истечение срока загрузки без аргументов процесса и текстов заданий.

Первоначальная загрузка получила отдельный предел 600 секунд и соответствующий Docker `start_period`; допустимое значение ограничено 1800 секундами. Пределы самого запроса 240 секунд и модельного шага 180 секунд сохранены. Повторная загрузка внутри активного запроса не может превысить оставшееся время запроса. Неверный исполняемый файл, ошибка запуска или версия не получают ложную готовность.

Новый model-only maintenance-образ наследует все 42 слоя прежнего `sha256:9c34055f78c9c2ede4aab7a3b697925c8bae00755ef849153154aa183e32319c` и заменяет только `index_translation_provider.py`. Контрольные суммы исходника и прежнего модельного lock проверены отдельным контейнером без сети и записи в образ. Сохраняются Index-Translate 9B Q4_K_M, `translator_ref`, веса, llama.cpp, 8 ГиБ RAM, два CPU и собственный socket-том. Собственная `.env` получила только открытые model-only настройки и не входит в Git. Одна наблюдавшаяся native-попытка сохранена в квитанции; новая инкарнация получает остаток две, не три свежих попытки. Регистрация дополнительных ролей или снятие чужих удержаний в этот объём не входят.

## Почему swap большой

На Mac установлено 24 ГиБ RAM. `footprint` для 100 доступных пользовательских процессов показал около 39 ГиБ суммарной учётной памяти; это не сумма текущего RSS и не виртуальные адресные пространства VSZ. Главные наблюдавшиеся значения: Docker VM — 16 ГиБ, два процесса VS Code — около 3,3 ГиБ каждый, ещё один renderer VS Code — около 1,7 ГиБ, Docker backend — около 1,1 ГиБ. Остаются дополнительные процессы редактора, браузера, Slack, DBeaver и ОС. Такой снимок показывает переподписку памяти, но не доказывает утечку конкретного приложения.

Занятый swap macOS составлял около 13,5–14 ГиБ, уровень давления — предупреждающий. Это не только исторический остаток: между двумя измерениями `vm_stat` за 239 секунд счётчик swap-in вырос на 1 075 485 страниц, swap-out — на 1 088 448 страниц при странице 16 КиБ, то есть около 70 и 71 МиБ/с соответственно. Чтение/запись swap нельзя отождествлять с одним только размером файла swap.

В Linux VM выделено около 15,6 ГиБ RAM и 1 ГиБ swap; гостевой swap почти занят. У модели в отдельном срезе было около 5,3 ГиБ учтённой памяти, из них примерно 5 ГиБ — файловые страницы весов, а собственный swap — около 6 МиБ. Счётчики `memory.events` для модели показали `max=0`, `oom=0`, `oom_kill=0`: доказательств, что текущий отказ вызван её лимитом 8 ГиБ или OOM, нет. Сокращать Docker VM по одному значению `MemAvailable` опасно: отображённые страницы весов считаются вытесняемыми, но нужны вычислению снова.

Сам по себе новый Python-файл не освобождает память других приложений и не обнуляет swap. Для устойчивой работы требуется уменьшить общий активный набор, закрыв ненужные приложения/окна, либо отдельно согласовать перераспределение или размещение нагрузки. Принудительная очистка swap, `purge`, остановка пользовательских приложений, изменение RAM VM и перезапуск Docker не выполнялись. Системный режим `footprint --all` недоступен без дополнительных прав; измерены только явно выбранные доступные пользовательские процессы, без содержимого их памяти.

## Проверки и выкладка

Прошли 312 собственных тестов переводчика, 17 явно пропущены; четыре подслучая успешны. Добавлены регрессии неподтверждённого reap, запрета второго процесса, сохранения исходного 503, повторной попытки, независимого загрузочного бюджета и изоляции модельного Compose override. Отдельный тест действительно создаёт, завершает и reaps собственный дочерний процесс. Строгая типизация изменённых файлов, Ruff и Black прошли закреплёнными инструментами. Проверка документационных ссылок не выявила ошибок; `git diff --check` прошёл. Прежние предупреждения Starlette/AnyIO не подавляются.

При первой операторской проверке хеша использован неверный относительный путь квитанции. Проверка исправлена абсолютным путём и подтвердила байты образа; повторная сборка не выполнялась. Первая попытка Compose заменить модель получила `tried to kill container, but did not receive an exit event`. Позднее точное чтение подтвердило старый контейнер в `Exited (137)`; до подтверждения повторный kill не отправлялся. Полные stdout/stderr и inspect сохранены, продолжение использует тот же образ и область модели, не повторяет весь инфраструктурный запуск.

Исправленный образ `sha256:786f421bb396f21d5bd1089e03d5fd1e663cb70a8aaf88eefab0d1b78c964a5d` установлен, новая модель запущена в 15:02:17 UTC. После подтверждённого удаления старой оболочки новому контейнеру возвращено каноническое имя `aelev-infrastructure-translator-model-1`. Сверка остальных 60 инфраструктурных контейнеров из предоперационного снимка не выявила замены ID или образов. Native-счётчик новой модели равен нулю, политика — `on-failure:2`; прежняя потраченная попытка сохранена отдельно.

**Работоспособность перевода после обновления пока не подтверждена.** В срезе около 15:11 UTC модель остаётся в первоначальной загрузке, Docker сообщает `starting`, дочерний llama.cpp существует, но готовность точного выпуска ещё не подтверждена. Успешных переводов 2146, опубликованных результатов 2434; последнее завершение — в 14:36:13 UTC, до замены модели. Поэтому рост относительно раннего счётчика 2093 нельзя приписывать исправленному образу. Число `FAILED` осталось 288, очередь не очищалась и её команды не менялись.

В том же срезе занято около 13,6 ГиБ swap macOS при предупреждающем давлении памяти; несколько других инфраструктурных проб также опаздывают. Это не положительная финальная приёмка и не основание объявлять весь стенд устойчивым. Установленная правка устраняет воспроизведённый дефект жизненного цикла, но не создаёт запас RAM: проверку завершённого перевода и устойчивости нужно повторить при достаточных ресурсах. Дополнительные массовые рестарты или изменения размещения без согласования не выполняются.
