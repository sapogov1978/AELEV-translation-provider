# translator-service — проверка Swagger

Дата: 2026-10-11 (Europe/Belgrade). Итог проверок API и браузера с явно переданным операторским удостоверением: PASS. Обычный браузер пользователя пока не настроен: импорт сертификата и изменение доверия macOS требуют отдельного согласования.

| Проверка | Результат |
|---|---|
| Сервисные регрессии окончательных исходников | 68 PASS на закреплённом Python 3.13.7; 19 явных пропусков разделены ниже. |
| Конфигурация через настоящий Docker CLI | 11 PASS отдельно; эти проверки пропущены внутри test-образа без Docker CLI. Всего 79 успешных сервисных проверок. |
| Качество изменённого кода | Black/Ruff PASS, строгий Pyright: 0 ошибок и предупреждений. |
| Сборка и модель | Собственный runtime собран; проверка закреплённой модели успешна. Версии Python, ОС и модели не менялись. |
| Самостоятельная и включённая поставки | Полное сравнение десяти translator-ролей прошло; корневой Compose с профилем ui разрешается без ошибки. |
| Публичный API | Пять прежних GET и одна схема OpenAPI; POST перевода отсутствует, частный HTTP не отдаёт Swagger. Документация и файлы Swagger имеют собственные защитные заголовки. |
| Настоящий TLS | С доверенным операторским удостоверением `/docs` возвращает HTTP 200; без него и с удостоверением чужой CA соединение отвергается до HTTP. Проверены CA/SAN и digest двух файлов Swagger. |
| Настоящий браузер | После OIDC-входа приняты ссылки собственной группы и компонента API, Swagger открыт без opener/Referer и CDN; выполнен настоящий `GET /healthz`, HTTP 200. [Подробный результат](swagger-live-result.md), [снимок](swagger.png), [тест](swagger.py). |
| Жизненный цикл API | Адресный restart собственного API завершил оба listener и запустил их заново; контейнер вернулся в healthy. Полный остановочный цикл всей поставки в этом прогоне не выполнялся. |
| PKI и секреты | Повторная подготовка поверх существующего каталога отвергнута, прежние ключи не изменились. `.env`, CA/серверные/операторские ключи, PKCS12 и пароль исключены из Git и контекста сборки. Сервер получает только три собственных TLS-файла, не ключ CA или операторское удостоверение. |

Внутри test-образа пропущены 11 конфигурационных проверок из-за отсутствия Docker CLI; они выполнены отдельно и прошли. Остальные восемь SQL-регрессий требуют изолированной одноразовой тестовой БД и не запускались на рабочем хранилище. Качество перевода, WAN, внешняя PKI, нагрузка и резервное восстановление не проверялись; прежние отчёты полного перевода не переписывались.

Первый сборочный запуск обнаружил порядок стадий Dockerfile; стадия файлов Swagger перенесена перед потребителями и сборка повторена успешно. Проверки типов и Black выявили несовместимую аннотацию генератора и форматирование нового утверждения; исправлены исходники, окончательные проверки прошли. Первый браузерный запуск использовал неверное имя оператора; повтор выполнен с существующей учётной записью без создания identity или подмены ответов.

Повтор перед доставкой подтвердил ту же ошибку без клиентского удостоверения: curl сообщает `Empty reply from server`, воспроизводя наблюдение пользователя `ERR_EMPTY_RESPONSE`. Это ожидаемый отказ TLS, но доступ в обычном браузере ещё не подготовлен. Тест предоставляет сертификат только собственному временному браузерному контексту и закрывает браузер; системное доверие и «Связка ключей» не изменялись. Подготовленная локальная PKI оставлена для дальнейшей работы в игнорируемом `runtime/api-pki`.
